Threads and background work

Windows, controls and timers belong to the GUI thread: the thread that creates the first [[Window]] and calls [[Application.Run]]. Doqua is not thread-safe, so other threads must not change them. Instead they hand the work to the GUI thread, which runs it between events. [[Application.IsGuiThread]] tells where the code runs.

Posting from a background thread

[[Application.Post]] queues an action for the GUI thread and returns at once. It can be called from any thread; the actions run in the order they were posted.

new Thread(() =>
{
    while (true)
    {
        var value = socket.ReadValue();                      // Blocks on the network: not on the GUI thread.
        Application.Post(() => valueLabel.Text = value.ToString());
    }
}) { IsBackground = true }.Start();

When the background code needs something from the GUI, such as a setting in a control, [[Application.InvokeAsync]] runs a function on the GUI thread and gives its result (or its exception) as a task:

var interval = await Application.InvokeAsync(() => intervalInput.Value);

async and await

The GUI thread has a synchronization context that posts to it, so an await started on the GUI thread (for example in an event handler) comes back to it. The work in between can run anywhere:

refresh.Click += async (sender, e) =>
{
    status.Text = "Reading...";
    var data = await client.GetStringAsync(url);          // No thread is blocked meanwhile.
    var summary = await Task.Run(() => Summarize(data));  // CPU work on the thread pool.
    status.Text = summary;                                 // Back on the GUI thread.
};

Progress<T> works the same way: create it on the GUI thread and its handler runs there, whatever thread reports.

var progress = new Progress<int>(percent => progressLabel.Text = $"{percent} %");
await Task.Run(() => Copy(source, target, progress));

Mistakes are reported

Changing a control shown in a window, or using a window, a [[Timer]] or the [[Clipboard]], from another thread throws an InvalidOperationException that says to use [[Application.Post]]. (Building controls that are not shown yet is allowed on any thread.) Without the check, such a change would work most of the time and corrupt the window now and then.

Notes

  • Posted actions and await continuations run between events; keep them short, like event handlers.
  • Do not block the GUI thread waiting for a worker (task.Wait(), .Result) while the worker waits for the GUI thread: that deadlocks. Use await.
  • Actions posted after [[Application.Run]] has returned never run.
